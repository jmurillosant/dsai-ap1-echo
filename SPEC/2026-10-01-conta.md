# Conta (2026-10-01)

## O quê e por quê
O sistema de contas é a porta de entrada para a rede social Echo. Ele permite que as pessoas se registrem, acessem suas contas (login) e encerrem suas sessões com segurança (logout), garantindo que apenas usuários autenticados possam interagir com as funcionalidades restritas no futuro.

## Critérios de aceitação

- **Cadastro:**
  - O sistema deve fornecer uma página com um formulário para registro contendo os campos: nome de usuário, e-mail, senha e confirmação de senha.
  - O sistema deve criar um novo usuário no banco de dados quando todos os dados enviados forem válidos.
  - Após um cadastro bem-sucedido, o sistema deve redirecionar o usuário automaticamente para a página de login.
  - O sistema deve apresentar mensagens de erro na própria página se o nome de usuário fornecido já estiver em uso.
  - O sistema deve apresentar mensagens de erro na própria página se o endereço de e-mail fornecido já estiver em uso.
  - O sistema deve apresentar uma mensagem de erro na própria página se as senhas fornecidas nos campos "senha" e "confirmação de senha" não forem idênticas.
  - As senhas nunca devem ser salvas no banco de dados em texto puro.

- **Login e Logout:**
  - O sistema deve fornecer uma página de login com campos para nome de usuário e senha.
  - O sistema deve autenticar o usuário e criar uma sessão ativa quando as credenciais estiverem corretas.
  - Após um login bem-sucedido, o sistema deve redirecionar o usuário para uma página temporária de boas-vindas (a home real será feita depois).
  - O sistema deve exibir uma mensagem de erro clara ("Credenciais inválidas") se o nome de usuário ou a senha estiverem incorretos, permanecendo na página de login.
  - O sistema deve fornecer um mecanismo (como um link ou botão) para encerrar a sessão (logout).
  - Após o logout, a sessão do usuário deve ser completamente destruída e o usuário deve ser redirecionado para a página de login.
  - Um visitante não autenticado que tente acessar páginas privadas deve ser redirecionado automaticamente para a página de login.

- **Testes Automáticos:**
  - O projeto deve conter testes automatizados que validem com sucesso as tentativas de cadastro com dados corretos.
  - Os testes devem falhar (rejeitar a criação) e validar a exibição de erros ao tentar cadastrar usuários com dados duplicados (nome de usuário ou e-mail).
  - Os testes devem simular e validar com sucesso os fluxos de login com credenciais corretas e os bloqueios de login com credenciais erradas.
  - Os testes devem simular a funcionalidade de logout e garantir que a sessão ativa seja encerrada.
  - Os testes devem validar que tentativas de acesso a rotas protegidas sem autenticação redirecionam o usuário para a página de login.

## Fora do escopo
- Recuperação de senha por e-mail ou redefinição de senha esquecida.
- Login via redes sociais de terceiros (Google, Facebook, etc.).
- Verificação de e-mail através de envio de link de confirmação (o cadastro é de aprovação imediata).
- Edição de perfil (foto de perfil, bio) - isso será tratado junto com a gestão de perfis em especificações futuras.
- Estilização visual complexa ou design responsivo aprofundado (um layout HTML simples funcional será suficiente nesta etapa).
